# Xelto Work Projects Design

## Goal

Add public-safe portfolio entries for Xelcode, ICR, Workflow, Holiday, Administration, eInvoicing, KSeF, and XELapps.

## Content Boundaries

Descriptions use only the supplied README and CV. They must not expose source code, customer data, internal URLs, tickets, credentials, or unsupported outcome claims.

## Presentation

The Work grid receives eight individual cards. Xelcode uses the supplied scanner-workflow image. The remaining entries use one neutral static placeholder asset until bespoke media is available.

Project data gains a link label so the existing personal projects retain their `github ->` link, while the Xelto entries use `Product overview ->` and point to the public Xelcode or Xelto product pages. Each detail page therefore labels external links accurately rather than presenting a company product page as source code.

## Project Coverage

- **Xelcode:** scanner-driven logistics and manufacturing workflows integrated with Oracle JD Edwards E1.
- **ICR:** document-AI interfaces for PDF handling, prompt configuration, analysis, and structured results.
- **Workflow:** approval and operational workflow modules.
- **Holiday:** employee leave administration workflows.
- **Administration:** users, groups, permissions, API keys, SSO, and system setup.
- **eInvoicing:** integration rules, document/log views, and PDF/XML workflows.
- **KSeF:** Polish e-invoicing interfaces and integration configuration.
- **XELapps:** client and application setup plus platform administration modules.
